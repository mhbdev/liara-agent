# ۱. شروع سریع — از صفر تا یک ایجنت آماده

پانزده دقیقه. لازم نیست چیزی از سرور، داکر یا DNS بدانید. هر مرحله می‌گوید چه
کاری می‌کند و اگر شکست خورد چه کنید.

## پیش‌نیازها

- یک حساب **لیارا** — <https://console.liara.ir>
- **Node.js نسخه ۲۰ یا بالاتر** — <https://nodejs.org> (ابزار خط فرمان لیارا به آن نیاز دارد)
- اگر ویندوز دارید: **Git Bash** — همراه Git for Windows نصب می‌شود. اسکریپت‌ها و
  قفل امنیتی با `sh` اجرا می‌شوند.
- **Claude Code** یا **Codex CLI**

## قدم ۱ — نصب ابزار خط فرمان لیارا

```bash
npm install -g @liara/cli
```

بررسی کنید:

```bash
liara --version
```

باید چیزی مثل `@liara/cli/9.6.0` ببینید. اگر دستور پیدا نشد، مسیر نصب Node در
PATH نیست — Node را دوباره نصب کنید و ترمینال را ببندید و باز کنید.

## نسخه کوتاه

اگر نمی‌خواهید مرحله‌به‌مرحله بخوانید، فقط یک دستور را اجرا کنید و بگذارید
خودش راهنمایی‌تان کند:

```bash
sh scripts/setup.sh
```

قدم‌های ۲ و ۳ را به ترتیب انجام می‌دهد — بررسی، ورود، تأیید، شناسایی حساب — و
می‌گوید بعدش چه بگویید. یا با ایجنت حرف بزنید: **`/liara-login`**.

بقیه این صفحه توضیح می‌دهد که دقیقاً چه کاری می‌کند و چرا.

## قدم ۲ — بررسی سلامت پکیج

```bash
sh scripts/setup.sh check
```

این دستور وجود ابزار لیارا، `curl`، `git` و Node را بررسی می‌کند، مطمئن می‌شود
قفل امنیتی وصل است و رمزها در گیت نادیده گرفته می‌شوند — و یک **تست خودکار از
قفل امنیتی** اجرا می‌کند تا ثابت شود محافظت‌ها واقعاً کار می‌کنند. هر چیزی که
`[FAIL]` است را قبل از ادامه درست کنید.

> چرا مهم است: در ویندوز اگر `sh` در دسترس نباشد، قفل امنیتی **بی‌صدا اجرا
> نمی‌شود** و ایجنت بدون محافظ کار می‌کند. `doctor.sh` تنها راه فهمیدن این است.

## قدم ۳ — وصل کردن حساب لیارا

```bash
sh scripts/setup.sh connect staging
```

یا به ایجنت بگویید «ورود» — خودش یک تب ترمینال با همین دستور باز می‌کند تا
بتوانید بدون خارج شدن از گفت‌وگو تایپ کنید.

اسکریپت خودش راهنمایی می‌کند. خلاصه:

۱. <https://console.liara.ir/API> را باز کنید
۲. یک مدت اعتبار انتخاب کنید — برای محیط آزمایشی **۱ ماه** مناسب است
۳. روی «ساخت کلید جدید» بزنید و کلید را کپی کنید. **فقط یک بار نمایش داده می‌شود.**
۴. وقتی اسکریپت پرسید، آن را بچسبانید

**آنچه تایپ می‌کنید نمایش داده نمی‌شود و توکن هرگز به هوش مصنوعی نمی‌رسد.**
این مهم‌ترین تصمیم طراحی این پکیج است: ایجنت با *استفاده* از کلید ثابت می‌کند
که کار می‌کند، اما هیچ‌وقت مقدار آن را نمی‌بیند.

بررسی:

```bash
sh scripts/setup.sh status
```

باید ببینید `staging stored ****a1b2`. همین شکل ماسک‌شده تنها چیزی است که ایجنت
می‌خواند.

> **چرا ایجنت نمی‌تواند این قدم را برایتان انجام دهد:** دستور
> `setup.sh connect` به یک ترمینال واقعی نیاز دارد. اگر ایجنت اجرایش کند، با
> کد خروج ۳ امتناع می‌کند. این محافظت ساختاری است — ایجنت «تصمیم نمی‌گیرد» که
> به توکن شما نزدیک نشود، بلکه **نمی‌تواند** به آن برسد.

### الان محیط اصلی (production) را راه نیندازید

جدی می‌گویم. ایجنت‌ها با محیط آزمایشی کامل کار می‌کنند. اینکه به یک ایجنت هوش
مصنوعی دسترسی سایت زنده‌تان را **ندهید**، یک مزیت است نه یک کمبود. وقتی واقعاً
چیزی برای انتشار داشتید، به [۰۲-credentials](02-credentials.md) برگردید.

## قدم ۴ — تنظیم پروژه

```bash
cp env.example .env
cp liara.json.example liara.json
```

بقیه را به ایجنت بسپارید — در Claude Code:

```
/liara-setup
```

**هر بار یک سؤال** می‌پرسد و برای هر سؤال یک پاسخ پیش‌فرض دارد، پس **«نمی‌دانم»
همیشه یک جواب کامل است.** نوع پروژه را تشخیص می‌دهد، `liara.json` را می‌نویسد و
فایل `OPERATIONS.md` را می‌سازد که توضیح می‌دهد چه چیزی راه‌اندازی شده.

مطمئن شوید بخش `healthCheck` در `liara.json` باقی بماند. همین بخش است که جلوی
زنده شدن نسخه خراب سایت را می‌گیرد — لیارا نسخه معیوب را منتشر نمی‌کند.

## قدم ۵ — استفاده

این‌ها را به زبان ساده بگویید، فارسی یا انگلیسی:

| شما می‌گویید | چه اتفاقی می‌افتد |
|---|---|
| «وضعیت سایت چطوره؟» | زنده بودن، سرعت، گواهی SSL، خطاهای اخیر |
| «منتشر کن» | بررسی قبل از پرواز ← نقشه ← انتشار ← تأیید سلامت |
| «کدوم پلن رو بخرم؟» | قیمت‌های زنده + مصرف واقعی شما |
| «خرابه، درستش کن» | تشخیص با مدرک، بعد یک وصله |

یا مستقیم از دستورها استفاده کنید:

```
/liara-status      /liara-deploy      /liara-plan
/liara-diagnose    /liara-report      /liara-setup
```

## قدم ۶ — اولین انتشار

```
/liara-deploy staging
```

ببینید چه می‌کند — و هیچ مرحله‌ای را رد نمی‌کند:

۱. **بررسی قبل از پرواز** — تست‌ها، بیلد، جست‌وجوی رمز لو رفته، بررسی تنظیمات.
   شکست بخورد → متوقف می‌شود.
۲. **نقشه** — چه تغییری، چه کسی تأثیر می‌بیند، هزینه، راه برگشت.
۳. **انتشار** — از طریق wrapper، با ثبت در گزارش.
۴. **تأیید** — سه بررسی سلامت پشت سر هم روی آدرس واقعی.
۵. **گزارش** — آدرس، چه چیزی تأیید شد، و چه چیزی **تأیید نشد**.

اگر گفت «منتشر شد ولی سالم نیست»، یعنی سیستم درست کار می‌کند. هیچ‌وقت نمی‌گوید
چیزی زنده است وقتی نیست.

## وقتی مشکلی پیش آمد

- سایت پایین است ← [۰۵-runbook](05-runbook.md)
- «رمز پیدا نشد» ← `sh scripts/creds.sh set staging`
- «BLOCKED by scripts/guard.sh» ← این عمدی است؛ پیام را بخوانید، خودش می‌گوید چه کنید
- توکن رد شد ← منقضی شده. یکی نو بسازید: <https://console.liara.ir/API>
