# ۰. نصب ایجنت‌ها در پروژه خودتان

این پکیج را در مخزنی نصب کنید که کد وب‌سایت شما در آن است. پکیج شامل
دستورالعمل و ابزار است؛ خود وب‌سایت شما را ندارد. کلون کردن پکیج به‌تنهایی
آن را در پروژه دیگری نصب نمی‌کند.

## پیش‌نیازها

- ایجنت کدنویسی خود را نصب کنید و طبق راهنمای خودش وارد حساب شوید. ورود به
  ایجنت با اتصال حساب لیارا جداست.
- Git، نسخه ۲۰ یا بالاتر Node.js و `curl` را نصب کنید. در ویندوز، تمام
  مثال‌های زیر را در **Git Bash** اجرا کنید؛ `sh` باید برای محیط اجرای دستور
  ایجنت هم در دسترس باشد.
- ترمینال را در **ریشه مخزن وب‌سایت**، کنار فایل‌های برنامه، باز کنید.
  تغییرات قبلی را قبل از افزودن پکیج بازبینی یا در گیت ثبت کنید.

## ۱. دریافت پکیج

از داخل مخزن وب‌سایت، یک نسخه جدا از پکیج را کنار آن کلون کنید:

```bash
git clone https://github.com/mhbdev/liara-agent.git ../liara-agent-pack
LIARA_PACK="$(cd ../liara-agent-pack && pwd)"
```

اگر قبلاً پکیج را دانلود یا کلون کرده‌اید، مقدار `LIARA_PACK` را مسیر کامل
همان پوشه بگذارید. دانلود ZIP از منوی **Code** مخزن هم ممکن است. نسخه منبع
را بیرون از مخزن وب‌سایت نگه دارید تا موقع انتشار اشتباهی همراه سایت نرود.

## ۲. افزودن فایل‌ها به پروژه

فقط **یکی** از دو روش زیر را انتخاب کنید. دستورها را از ریشه مخزن وب‌سایت،
در همان ترمینالی که `LIARA_PACK` را تنظیم کردید، اجرا کنید.

### نصب اول، بدون مسیرهای هم‌نام

این بلوک قبل از کپی همه مسیرهای مقصد را بررسی می‌کند. اگر مسیری از قبل
وجود داشته باشد، هیچ تغییری نمی‌دهد؛ از روش ادغام پایین استفاده کنید.

```bash
(
  set -eu
  for item in AGENTS.md CLAUDE.md .claude scripts tests/guard-cases.txt \
    docs/en docs/fa env.example liara.json.example OPERATIONS.template.md
  do
    if [ -e "$item" ] || [ -L "$item" ]; then
      printf 'Already exists: %s. Use the merge method.\n' "$item" >&2
      exit 1
    fi
  done

  mkdir -p tests docs
  for item in AGENTS.md CLAUDE.md env.example liara.json.example OPERATIONS.template.md
  do
    cp "$LIARA_PACK/$item" "$item"
  done
  cp -R "$LIARA_PACK/.claude" .claude
  cp -R "$LIARA_PACK/scripts" scripts
  cp "$LIARA_PACK/tests/guard-cases.txt" tests/guard-cases.txt
  cp -R "$LIARA_PACK/docs/en" docs/en
  cp -R "$LIARA_PACK/docs/fa" docs/fa

  printf '\n# Liara credentials and local state\n' >> .gitignore
  printf '%s\n' '.liara/' '.env' '.env.*' '!.env.example' 'state/' >> .gitignore
)
```

فایل README پکیج، پوشه `.git`، رمزها و وضعیت محلی کپی نمی‌شوند. README و
کد برنامه خودتان سر جای خود می‌مانند.

### پروژه‌ای با تنظیمات ایجنت یا پوشه‌های مشترک

با ویرایشگر یا ابزار مقایسه فایل، مسیرهای زیر را از `LIARA_PACK` به
**همان مسیرها** در مخزن وب‌سایت ادغام کنید. فایل‌های جدید را کپی کنید؛
فایل‌های موجود را قبل از تغییر مقایسه کنید.

| منبع ← مقصد در پروژه | روش ادغام |
|---|---|
| `AGENTS.md` | قرارداد لیارا را به دستورالعمل‌های پروژه اضافه کنید و قوانین فعلی را نگه دارید. تعارض قوانین را قبل از عملیات حل کنید. |
| `CLAUDE.md` | دستورالعمل‌های فعلی را نگه دارید؛ راهنمای Claude پکیج و الزام خواندن `AGENTS.md` را اضافه کنید. خط `@AGENTS.md` قرارداد را صریحاً وارد زمینه Claude Code می‌کند. |
| `.claude/agents/liara-*.md` | هر شش نقش را اضافه کنید و ایجنت‌های دیگر را نگه دارید. |
| `.claude/commands/liara-*.md` | هر هفت دستور را اضافه کنید و دستورهای دیگر را نگه دارید. |
| `.claude/skills/liara-ops/` | پوشه کامل مرجع را کپی کنید؛ محیط‌های دیگر هم می‌توانند آن را از همین مسیر بخوانند. |
| `.claude/settings.json` | ورودی‌های `hooks.PreToolUse` و آرایه‌های `permissions.allow` و `permissions.deny` را با ورودی‌های فعلی ادغام کنید. دستور قفل و قوانین منع را دست‌نخورده نگه دارید؛ کل فایل تنظیمات را جایگزین نکنید. |
| `scripts/` | همه اسکریپت‌ها، از جمله `lib/common.sh`، را اضافه کنید. اگر اسکریپت هم‌نامی متفاوت است، قبل از ادامه تعارض را حل کنید. |
| `tests/guard-cases.txt` | داده تست قفل را اضافه کنید و تست‌های دیگر پروژه را نگه دارید. |
| `docs/en/` و `docs/fa/` | راهنماها را اضافه کنید تا ارجاع‌های دستورالعمل‌ها کار کنند. سندهای هم‌نام را ادغام کنید. |
| `env.example` و `liara.json.example` و `OPERATIONS.template.md` | قالب‌ها را اضافه کنید و تنظیمات فعلی برنامه را نگه دارید. |
| `.gitignore` | قواعد `.liara/`، `.env`، `.env.*`، `!.env.example` و `state/` را بدون حذف قواعد فعلی اضافه کنید. |

پوشه‌های `scripts/` و `.claude/` باید در ریشه پروژه بمانند؛ هوک‌ها، دستورها
و اسکریپت‌ها به این مسیرها ارجاع می‌دهند. نصب زیر `tools/liara/` یا کپی
کردن فقط فایل‌های نقش‌ها، پکیج کامل را متصل نمی‌کند.

هرگز `.liara/`، `.env`، `state/` یا تأییدیه‌ها را از نصب دیگری کپی نکنید.
قواعد نادیده‌گیری، فایل‌های قبلاً ثبت‌شده در گیت را حذف نمی‌کنند؛ قبل از
اتصال حساب، مشکل رمزهای ثبت‌شده را بدون چاپ محتوایشان حل کنید.

## ۳. فعال‌سازی محیط کدنویسی

دستور دقیق شروع هر محیط در [راهنمای سرویس‌ها](04-providers.md) آمده است:

| محیط | اتصال به پروژه | اولین استفاده |
|---|---|---|
| **Claude Code** | `CLAUDE.md`، نقش‌ها، دستورها، مهارت و تنظیمات ادغام‌شده | در مخزن وب‌سایت دوباره اجرا کنید؛ نقش `liara-connect` را بخواهید یا `/liara-login` را اجرا کنید. |
| **Codex CLI / IDE / desktop** | `AGENTS.md` در ریشه؛ خواندن نقش‌ها با ارجاع به فایل | مخزن وب‌سایت را باز کنید و پیروی از `.claude/agents/liara-connect.md` را بخواهید. برای CLI از گزینه‌های محدودسازی راهنمای سرویس‌ها استفاده کنید. |
| **Cursor** | `AGENTS.md` در ریشه؛ فایل اختیاری `.cursor/rules/liara.mdc` | مخزن وب‌سایت را باز کنید و نقش را با مسیر فایل بخواهید. |
| **Windsurf** | `AGENTS.md` در ریشه؛ فایل اختیاری `.windsurf/rules/liara.md` | مخزن وب‌سایت را باز کنید و نقش را با مسیر فایل بخواهید. |
| **Aider** | بارگذاری قرارداد، مرجع و نقش با `--read` | دستور راهنمای سرویس‌ها را اجرا کنید. |
| **Gemini CLI** | وارد کردن `AGENTS.md` از `GEMINI.md` | در مخزن وب‌سایت دوباره اجرا کنید و نقش را با مسیر فایل بخواهید. |
| **ایجنت‌های دیگر** | بارگذاری صریح `AGENTS.md`، مهارت لیارا و فایل نقش | از پرامپت عمومی راهنمای سرویس‌ها استفاده کنید؛ عملیات به اجرای دستورهای shell نیاز دارد. |

روش کپی بالا فایل فعلی `.codex/config.toml` شما را تغییر نمی‌دهد. تنظیمات
اختیاری Codex و شناسایی مهارت در راهنمای سرویس‌ها توضیح داده شده است.
نصب فقط مهارت لیارا، اسکریپت‌ها و نقش‌ها را نصب نمی‌کند.

این نصب مخصوص یک پروژه است و از طریق گیت همان پروژه با تیم به اشتراک
گذاشته می‌شود. کپی نقش‌ها به `~/.claude/agents/` یا مهارت به
`~/.agents/skills/`، ابزارها و قرارداد را در همه پروژه‌ها نصب نمی‌کند.

## ۴. بررسی، اتصال، سپس تنظیم پروژه

در مخزن وب‌سایت:

```bash
npm install -g @liara/cli
sh scripts/setup.sh check
sh scripts/test-guard.sh
```

خطاها را قبل از ادامه برطرف کنید. این بررسی وجود فایل‌ها و نمونه‌های قفل
را می‌آزماید؛ ثابت نمی‌کند ایجنت دستورالعمل‌ها را بارگذاری کرده یا هوک
واقعاً فعال است. بررسی فعال‌سازی مخصوص سرویس را هم انجام دهید.

نسخه فعلی مخزن دو شکست ثبت‌شده در تست قفل دارد. اگر این نمونه‌ها شکست
خوردند، [شکاف‌های امنیتی شناخته‌شده](07-security.md) را ببینید؛ آن‌ها را
نادیده نگیرید و محافظت اجرای دستور در نصب را تأییدشده اعلام نکنید.

سپس **خود شما، انسان**، در یک ترمینال واقعی اجرا کنید:

```bash
sh scripts/setup.sh connect staging
```

توکن را در چت نفرستید. بعد از آن، ایجنت می‌تواند `setup.sh status`،
`setup.sh verify staging` و `setup.sh discover staging` را برای بررسی اتصال،
بدون دیدن توکن، اجرا کند.

برای تنظیم `liara.json` و ساخت `OPERATIONS.md` مخصوص وب‌سایت خودتان، به
[قدم ۴ شروع سریع](01-quickstart.md#قدم-۴--تنظیم-پروژه) بروید.

## به‌روزرسانی نصب

نسخه منبع جداگانه را به‌روز کنید، تفاوت فایل‌ها در گیت را ببینید و روش
ادغام را فقط برای فایل‌های تغییرکرده تکرار کنید. تغییر تنظیمات را خودتان
بازبینی کنید؛ دستورالعمل‌ها، هوک‌ها و اسکریپت‌های پروژه را یکجا جایگزین
نکنید. پس از هر به‌روزرسانی بررسی‌های نصب را تکرار کنید. رمزها و تأییدیه‌ها
محلی می‌مانند و بین پروژه‌ها کپی نمی‌شوند.
