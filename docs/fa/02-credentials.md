# ۲. رمزها و دسترسی‌ها — ایجنت چطور دسترسی می‌گیرد بدون اینکه کلید را ببیند

## اصل ماجرا

**ایجنت هوش مصنوعی هرگز توکن شما را نمی‌بیند.** نه یک‌بار، نه کوتاه، نه به شکل
«امن».

این صرفاً احتیاط نیست. هر چیزی که وارد حافظه مدل شود ممکن است سر از یک لاگ،
یک درخواست کش‌شده، یک گزارش خطا یا یک خلاصه دربیاورد. تنها توکنی که از این راه
لو نمی‌رود، توکنی است که اصلاً آنجا نبوده.

پس مسیر این است:

```
  کلیپ‌بورد شما  ──►  scripts/creds.sh  ──►  فایل رمزنگاری‌شده روی دیسک شما
                              │
                              └──►  موقع اجرا توسط scripts/liara.sh
                                     به ابزار لیارا تزریق می‌شود

  چیزی که ایجنت می‌بیند:  ****a1b2   و اینکه دستور موفق بود یا نه
```

ایجنت درستی کلید را از روی **اثرش** تأیید می‌کند، نه از روی مقدارش.

## گرفتن توکن

۱. <https://console.liara.ir/API> را باز کنید
۲. مدت اعتبار را انتخاب کنید. گزینه‌ها: ۱ ساعت، ۱ روز، ۷ روز، ۱ ماه، ۶ ماه، ۱ سال.

   | محیط | پیشنهاد | چرا |
   |---|---|---|
   | آزمایشی (staging) | ۱ ماه | راحت است؛ بدترین حالت، یک اپ آزمایشی قابل بازسازی |
   | اصلی (production) | ۱ روز یا ۷ روز | عمر کوتاه = دامنه خسارت کوچک |

۳. روی «ساخت کلید جدید» بزنید
۴. فوراً کپی کنید — **فقط یک‌بار نمایش داده می‌شود**

## ذخیره کردن

```bash
sh scripts/setup.sh connect staging
sh scripts/setup.sh connect production    # فقط وقتی واقعاً لازم شد
```

یا به ایجنت **liara-connect** بگویید «ورود» — بررسی‌ها را انجام می‌دهد، یک تب
ترمینال با همین دستور باز می‌کند تا در آن تایپ کنید، بعد تأیید می‌کند و نتیجه
را گزارش می‌دهد. گفت‌وگو در چت است؛ رمز در ترمینال می‌ماند.

ورودی مخفی است. هیچ چیزی چاپ، ثبت یا لاگ نمی‌شود.

**این قدم را ایجنت نمی‌تواند انجام دهد.** `setup.sh connect` به یک ترمینال
واقعی نیاز دارد، پس اگر ایجنتی اجرایش کند کد خروج ۳ می‌گیرد و پیامی می‌بیند که
می‌گوید از شما بخواهد. محافظت همین است: نه قانونی که ایجنت رعایت می‌کند، بلکه
کاری که **نمی‌تواند** بکند.

کجا ذخیره می‌شود:

| سیستم | محل | محافظت |
|---|---|---|
| ویندوز | `.liara/token.<env>.dpapi` | DPAPI — رمزنگاری‌شده با کاربر ویندوز شما؛ کاربر دیگر روی همان دستگاه نمی‌تواند بخواند |
| مک / لینوکس | `.liara/token.<env>` | دسترسی `0600` — فقط مالک فایل |

هر دو در `.gitignore` هستند. پوشه `.liara/` در فهرست `permissions.deny` ایجنت هم
هست، یعنی حتی اگر تلاش کند نمی‌تواند بخواند.

## بررسی بدون افشا

```bash
sh scripts/setup.sh status
```

```
  staging     stored    ****a1b2   storage=DPAPI(user-bound)
  production  MISSING   run: sh scripts/setup.sh connect production
  CLI:        @liara/cli/9.6.0
  LIARA_ENV:  staging
```

ماسک‌شده و بی‌خطر برای خواندن توسط ایجنت. برای اینکه مطمئن شوید توکن واقعاً کار
می‌کند:

```bash
sh scripts/setup.sh verify staging
```

## دو محیط، عمداً جدا

ایجنت به‌صورت پیش‌فرض فقط **محیط آزمایشی** را دارد. محیط اصلی جداست و باید
خودتان فعالش کنید.

این کار بدترین حالت را از «سایت زنده‌ات رفت» به «اپ آزمایشی رفت، دوباره بسازش»
تبدیل می‌کند. اگر فقط محیط آزمایشی را راه بیندازید، ایجنت‌ها همچنان برای پایش،
تشخیص و آماده‌کردن وصله کاملاً مفیدند.

```bash
# پیش‌فرض ایجنت
LIARA_ENV=staging sh scripts/liara.sh app list

# محیط اصلی، فقط خواندن — مجاز است
LIARA_ENV=production sh scripts/liara.sh app list

# محیط اصلی، نوشتن — تا وقتی انسان تأیید نکند مسدود است
LIARA_ENV=production sh scripts/liara.sh deploy --app my-site
# ← BLOCKED: production write without approval
```

برای اجازه دادن به **یک** عملیات روی محیط اصلی:

```bash
sh scripts/approve.sh grant prod-write
```

یک‌بار مصرف. بعد از ۱۵ دقیقه منقضی می‌شود. **ایجنت نمی‌تواند خودش این را بسازد**
— یک پرامپت نمی‌تواند فایل بنویسد. کل ماجرا همین است.

## اگر توکن لو رفت

از لحظه‌ای که جایی ظاهر شد که نباید — از جمله در یک پیام چت — آن را لو رفته
فرض کنید.

۱. <https://console.liara.ir/API> ← آن کلید را حذف کنید
۲. یک کلید جدید بسازید
۳. `sh scripts/creds.sh set <env>`
۴. `state/audit.log` را ببینید که با آن چه کارهایی انجام شده

عمر کوتاه توکن، خسارت را محدود می‌کند. دلیل پیشنهاد ۱ تا ۷ روز برای محیط اصلی
همین است.

## چرخش کلیدها

| توکن | هر چند وقت |
|---|---|
| آزمایشی | وقتی منقضی شد، ماهانه |
| اصلی | هر ۱ تا ۷ روز، و بلافاصله بعد از خروج هر نفر از پروژه |

حذف محلی (و بعد ابطال در کنسول):

```bash
sh scripts/creds.sh remove production
```

## کارهایی که ایجنت از آن‌ها مسدود است

این‌ها با `scripts/guard.sh` و `permissions.deny` اعمال می‌شوند، نه با توصیه:

- خواندن `.liara/token.*` ← مسدود
- `sh scripts/creds.sh print-token` ← مسدود
- `cat .env` و `.env.production` ← مسدود
- `curl` با توکن در هدر ← مسدود
- `--api-token` در خط فرمان ← مسدود
- صدا زدن مستقیم `liara` (که wrapper را دور می‌زند) ← مسدود

خودتان امتحان کنید:

```bash
sh scripts/test-guard.sh
```
